the idea

What is Redis, really?

Most databases store their data on a disk — a hard drive or an SSD. Even a fast SSD has to locate a file, open it, and read it back. Redis skips the disk entirely. It keeps all of its data in your computer's memory (RAM) — the same place your open apps and browser tabs already live.

RAM is roughly 100,000 times faster to access than a disk. That trade — give up permanent storage, get almost unimaginable speed — is the entire idea behind Redis. It's why companies use it for the things that need to happen right now: showing you're logged in, counting a "like," deciding who's winning a game.

Every key gets a slot in memory

Redis is fundamentally a giant dictionary: you give it a key, it gives back the value stored under that key. No searching, no scanning — it jumps straight to the slot. how you talk to it

A handful of short commands

You don't need a query language to use Redis. You send short, plain commands: SET a key, GET it back, EXPIRE it after a while, or DEL it outright. Each one is designed to run in well under a millisecond.

what you can store

Five shapes of data

Redis isn't limited to plain text values. It understands a handful of built-in shapes, and it manipulates each one directly — no need to pull the whole thing out, change it, and put it back.

"session:8841" → "active"

String

One value under one key — a name, a number, a JSON blob. The simplest shape, and the most common.

List

An ordered sequence you can push to or pop from either end — like a stack of plates, or a line at a coffee shop.

name
"Alex"
age
29

Hash

A mini object — one key holding several field-value pairs. Think of it as a single row in a table.

Set

A bag of unique values with no particular order — perfect for tracking "has this already happened" without duplicates.

Sorted set

Like a Set, but every member carries a score — Redis keeps it sorted automatically. This is how leaderboards get built.

why it's fast

Memory beats disk, by a lot

These bars aren't drawn to a normal scale — RAM is so much faster than a spinning hard drive that a fair scale would make the other two invisible. Roughly speaking, moving from RAM to an SSD to a hard disk costs you one to two extra zeroes at every step.

RAM (Redis)~100 nanoseconds
SSD~100 microseconds
Hard disk~10 milliseconds
what people build

Where Redis actually gets used

Redis isn't usually your main database — it's rarely used to store the only copy of something important. It shines as the fast layer that sits in front of, or alongside, a slower database.

01

Caching

Store the answer to an expensive question once, so the next 10,000 people asking it get an instant reply.

02

Session storage

Remember that you're logged in, on every request, without hitting the main database each time.

03

Leaderboards

Sorted sets keep rankings updated and readable in real time, no re-sorting required.

04

Pub/Sub messaging

One part of a system shouts a message, and every other part that's listening hears it instantly.

05

Rate limiting

Count how many requests someone made in the last minute, and block them if they went over.

06

Job queues

Lists let background workers pick up tasks in order, one at a time, without stepping on each other.

Redis: everything above, held in memory, answered in microseconds.
